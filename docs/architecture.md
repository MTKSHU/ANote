# ANote 架构

网页与 Electron 共用 React 工作台、Tiptap 编辑器和富文本模型。Yjs／Hocuspocus 处理实时协作，PostgreSQL 保存协作状态及业务数据。NestJS API 同时提供网页、HTTP、WebSocket 和 MCP。独立 Worker 处理媒体任务。

## 数据

数据库保存用户、团队、知识库、目录、笔记、授权、评论、历史、暂存上传与附件索引。原件、上传暂存、衍生预览和桌面分发包分别存储。Worker 只读原件，API 只读分发目录；文件权限和引用权限在请求时检查。

SQL 迁移按文件记录校验值并在事务锁中执行，不改写已应用迁移。数据库、协议与内部包统一使用 `anote` 标识，详见[命名约定](naming.md)。

## 权限

平台管理员管理站点配置及账号，其角色不绕过用户私人内容权限。团队管理员管理本团队的内容、成员和安全策略；普通团队成员默认阅读、评论可访问内容，编辑他人笔记需要明确授权。受限知识库继续约束团队笔记访问。

个人笔记默认私有，团队笔记默认团队可见。笔记创建者拥有自己的管理权限；平台停用账号、移出团队、撤销授权和失效外链在服务端及协作连接上重新校验。

跨库移动仅限本人个人知识库之间或同一团队内，要求源笔记管理权限与目标创建权限；整理他人笔记还须保留作者的目标访问。移动先预览，保留 ID、正文、附件、评论和历史，并撤销旧指定授权与外链。

## 同步与保存

结构化富文本是增强表格、导图、媒体排版及评论定位的依据。服务器持续保存协作状态，有正文变化时按分钟间隔保留历史；命名版本单独记录。客户端关闭前等待本地写入，断网时可继续编辑已有缓存。

本地受管 Markdown 与 `.anote` 基准、附件清单配合完成双向同步。可合并的普通文本和样式修改尝试合并，重叠或结构变化进入冲突处理并保留本地内容；缺失文件不自动传播删除。无需登录的个人模式使用所选目录中的 `.anote` 保存数据，不自动上传至团队。

## 当前边界

服务端为单 API 实例设计，独立备份需由部署者配置。音视频播放取决于原编码，没有自动转码。三维预览支持自包含 GLB、OBJ 几何、普通 PLY、SPLAT 与规定格式 Gaussian PLY；不执行上传的脚本或原生引擎工程。Windows／macOS 原生运行、系统密钥库、签名与公证需单独验证。
